2. APP PURPOSE AND BEHAVIOR
===========================

The user has a rooted Red Magic 11 Pro / NX809J on Android 16, aftermarket
wireless Android Auto units in cars and on a motorcycle, a watch, and Bluetooth
audio devices. Android Auto can seize audio or send it to the phone/watch
instead of the chosen earbuds or car stereo. AAARP tries to keep the chosen
Bluetooth target while preserving calls, voice interactions, and normal music
app behavior.

Active app/package:
  :app -> dev.voxvargr.aaarp, version 0.1.0 / code 1, minSdk 23
  :volume-up -> dev.voxvargr.aaarp.volumeup, 0.1.0 / code 1, minSdk 23
  :volume-down -> dev.voxvargr.aaarp.volumedown, 0.1.0 / code 1, minSdk 23
  :volume-shortcut-common -> shared Android library, minSdk 23
  :aa-trust-hook -> dev.voxvargr.aaarp.aatrusthook, 0.5.0 / code 5, minSdk 30

Compile/target SDK is 36 for app APK modules. Main UI uses Java/platform Views.
There is no Kotlin/Compose/Room conversion in this project. Do not confuse it
with the separately discussed YTM Loudness Normalizer or Vox Automation apps.

The newer app has:
- Bluetooth target selection and watchdog routing.
- Wireless Android Auto identity detection and per-unit profiles.
- Root audio-policy/media routing support plus public API fallbacks.
- Foreground monitoring, boot restore, battery exemption request.
- Optional GPS warmup, sound/ducking/mute/media-normalization settings.
- Call/ringing/communication and Assistant/guidance routing protections.
- Diagnostic exports, automatic logs, installed-APK build identity.
- JSON Backup Settings / Restore Settings.
- Separate Volume + / Volume - helpers and an optional LSPosed dock hook.

The detector requires Android Auto process evidence and a specific recognized
Wi-Fi Android Auto connection. Wired-only AA without that identity can be
treated as idle; do not promise wired AA support based on this source alone.

Volume helpers must not become media players or steal YouTube Music's session,
artwork, playback buttons, or audio focus. The hook targets tested Android Auto
17.3 internals to display Maps / YouTube Music / Volume + / Volume - in four
native dock slots and route taps to main AAARP while retaining the current
screen. It is version-specific; future AA changes require renewed inspection.
See the architecture report and README for authentication and fail-closed rules.

4. SIGNING AND INSTALLATION
===========================

The user accepts a different signing key on the new machine. This does not
automatically make Android accept an in-place update over the old certificate.

- Debug builds normally use the new user's ~/.android/debug.keystore.
- Main AAARP and both volume helper APKs must be built with the SAME certificate
  because their bridge is signature-protected. Build the set together.
- Do not mix old-key helpers with a new-key main APK.
- The LSPosed module is a separate package; its updates are also subject to
  Android signing checks. Its bridge checks the allowed Android Auto caller as
  described in current source; do not weaken authentication to bypass a mismatch.
- Private signing keys are intentionally absent from Git.
- Before replacement, use Backup Settings to export CURRENT AAARP settings and preserve the installed
  APKs/diagnostics separately. Record hashes and certificates.
- An install signature mismatch must not trigger automatic adb uninstall.
  Uninstall can erase private app settings. Only replace after a current backup
  exists and the user has chosen the intended replacement.
- Version 0.1.0 / code 1 has been reused. Compare SHA256, package update time,
  source HEAD/dirty diff and signing certificate, not version name alone.

Expected APKs:
  app/build/outputs/apk/debug/app-debug.apk
  volume-down/build/outputs/apk/debug/volume-down-debug.apk
  volume-up/build/outputs/apk/debug/volume-up-debug.apk
  aa-trust-hook/build/outputs/apk/debug/aa-trust-hook-debug.apk

After backups/signing are resolved, install the main app first, then helpers
and the optional hook. Example commands for a compatible already-signed set:
  adb install -r app/build/outputs/apk/debug/app-debug.apk
  adb install -r volume-down/build/outputs/apk/debug/volume-down-debug.apk
  adb install -r volume-up/build/outputs/apk/debug/volume-up-debug.apk
  adb install -r aa-trust-hook/build/outputs/apk/debug/aa-trust-hook-debug.apk

For each built APK:
  Get-FileHash -Algorithm SHA256 <APK>
  apksigner verify --print-certs <APK>

apksigner is in SDK build-tools; use that machine's installed path. A build alone
does not verify the currently installed artifact. BuildIdentity diagnostics hash
the installed main base APK.

5. SETTINGS AND DEVICE ACCESS
=============================

Use the app's Backup Settings to save a fresh JSON file before any reinstall.
Stop Monitor before using Restore Settings through the document picker. Import
does not stop an already-running monitor. SettingsBackup format is
dev.voxvargr.aaarp.settings, version 1, with typed preferences. Restore clears
current preferences and replaces them. It deliberately omits monitor_enabled
and legacy media relay settings. Starting the monitor afterward is manual.

An exported access snapshot can attempt root-assisted runtime permission and
battery-exemption restoration if root was enabled and is available. It cannot
transfer the root manager's trust decision or LSPosed enable/scope state, and
must not be treated as proof every access grant worked.

typed JSON fallback derived from the latest August 3 XML. It is not a fresh
phone export. Prefer current export; do not overwrite today's settings with
